# Evidence Policy

## Evidence layers

Each case record should separate:

1. **Observed** — directly supported facts about the source material.
2. **Abstracted** — mechanism interpretation derived from those facts.
3. **Derived** — new ideas, analogies, formulas or execution proposals created
   by this project.

Derived content must never be written back as an observed fact.

## Prior art

A mechanism should be checked against historical and cross-domain precedents
before being described as novel.

Near-identical reskins are not new mechanisms.

## Counterevidence

The research set must intentionally include:

- weak or ordinary outcomes;
- execution failures;
- weak brand/product linkage;
- overclaimed case studies;
- trend-driven work with low transferability;
- AI work where AI is incidental rather than necessary.

## Cross-domain transfer

Shared mechanism does not mean shared implementation.

A video mechanism, static visual mechanism, title/copy mechanism and service
mechanism may share an abstract relation while requiring different execution
objects, constraints and validation.

## Validation hierarchy

A useful default hierarchy is:

```text
source evidence
→ mechanism hypothesis
→ prior-art check
→ internal pressure test
→ actual output
→ human review
→ regression / counterexample check
→ controlled promotion or rejection
```

Document completeness is not production validation. A single success is not a
general rule.
